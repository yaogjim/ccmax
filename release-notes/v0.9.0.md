# ccmax v0.9.0

本次新增 **Telegram 交互式问答卡片**：模型通过 `AskUserQuestion` 提问时，不再需要手工拼 JSON，直接在 Telegram 里点按钮即可逐题作答并一次提交。同时重构项目/会话选择与共享问答流，更新中英文 Telegram 文档。

> **安装范围与签名**：本版本仅提供 macOS Apple Silicon（ARM64）安装包，沿用该分支的本地自签名方式，未经 Apple Developer ID 签名和公证。首次打开可能被 Gatekeeper 拦截，请仅在确认来源可信后按下方步骤安装。Windows、Linux 和 Intel Mac 安装包不在本次发布范围内。

## Telegram 问答卡片

- 模型通过 `AskUserQuestion` 提问时，Telegram 发送一张带选项按钮的卡片，按题目逐题作答：单题点选选项或直接发文字都会提交整份答案；多题点选逐题收齐，到摘要页点「提交全部」一次送出。
- 支持回复某条问题消息来定向作答；多条待答问题时普通文字不会猜最新一条，需要先点选目标。
- `/answer` 可以不带请求 ID：唯一待答时 `/answer Axios` 即可；多题用 JSON，键可以是完整问题文本或从 1 起的题号，例如 `/answer {"1":"React","2":"SQLite"}`。旧的 `/answer <id> {...}` 形式仍然有效。
- 草稿只留在当前进程内存中，不写入会话文件；`/stop` 使当前提问失效但不代发拒绝，`/deny` 才会把拒绝回传给桌面会话。

## 项目与会话选择

- `/projects` 列出最近项目并直接用按钮新建会话；新增 `/sessions` 查看并恢复当前项目的历史会话。
- `/resume` 在已绑定项目时默认列出当前项目历史，未绑定时先选择项目；新增 `/cancel` 取消当前的项目或会话选择。

## 内部重构

- 共享问答流拆分到 `adapters/common/ask-user-question.ts`（问题解析、答案校验、流程状态机），`permission.ts` 转为再导出，避免权限与问答逻辑继续耦合。
- Telegram 侧新增 `question-controller.ts` 承载卡片渲染、回调按钮路由与墓碑清理；回调数据带随机前缀与 128 条墓碑上限，防重放与内存膨胀。
- 解析层硬化：拒绝原型污染键（`__proto__`、`constructor`、`prototype`）、重复或空问题文本；非法选项降级为自由文本而不是整体失败。

## 安装与更新

- macOS Apple Silicon：下载 `ccmax-0.9.0-mac-arm64.dmg`，打开后拖入「应用程序」。
- 首次打开若被 Gatekeeper 拦截：在「系统设置 → 隐私与安全性」中点「仍要打开」，或在终端执行 `xattr -dr com.apple.quarantine /Applications/ccmax.app`。
- 已安装 v0.6.x–v0.8.x 的用户可直接用新 DMG 覆盖安装，配置与会话数据保持不变。
