# ccmax v0.10.0

本次新增 **Telegram 双入口**：在原有专属 Bot 之外，可以再接一个仅供本人使用的公共 Bot，订阅多个会话、接收带来源标识的报告，并用回复或 `/to` 把文字送回指定会话；该会话的提问与审批也能在公共入口直接处理。同时更新中英文 Telegram 文档。

> **安装范围与签名**：本版本仅提供 macOS Apple Silicon（ARM64）安装包，沿用该分支的本地自签名方式，未经 Apple Developer ID 签名和公证。首次打开可能被 Gatekeeper 拦截，请仅在确认来源可信后按下方步骤安装。Windows、Linux 和 Intel Mac 安装包不在本次发布范围内。

## 双入口与身份隔离

- Telegram 可同时接两个私聊 Bot：**旧 Bot 是专属入口**，继续只绑定一个会话，沿用配对、命令、流式回复、媒体和权限按钮；**新 Bot 是公共入口**，只接受配对后的唯一操作者私聊。「公共」指多个会话共用这个入口，不是 Telegram 群组，也不向其他人开放。
- 两入口配置、配对、运行状态完全独立：保存专属 Token 不改公共配置，保存公共配置不动专属 Token；公共入口默认关闭，旧安装升级后仍只用原来的专属 Bot，不必重新配对。
- 公共配对码有独立作用域与有效期，只有第一个有效配对成为唯一操作者；更换操作者必须在桌面端确认重置，不能被第二个 Telegram 用户覆盖。
- 同一用户、相同 `chatId`、两个 Bot 同时运行时，绑定、去重、消息映射与回调互不串扰；启动时校验两个配置不能指向同一个 Bot。
- 旧 `adapter-sessions.json` 前向迁移：仅将能确认归属的旧 Telegram 绑定映射至专属入口，保留其他平台数据。

## 订阅与多会话报告

- 公共入口没有隐式「当前会话」：用 `/subscribe <会话编号>` 加入、`/unsubscribe` 退出、`/subscriptions` 查看订阅与投递状态，也可在桌面端粘贴完整 `sessionId` 加入。
- 报告形如 `[ccmax · 项目 · 会话标题 · S7K2] 已完成：……`：明确展示项目、会话标题与稳定短编号；标题可改，短编号不变。
- 报告先持久化待发（outbox）再调用平台：待发、发送中、已确认、失败、结果不确定五种状态区分清楚；超时或缺回执记为「不确定」，不当成成功。Telegram 429 按 `retry_after` 退避并有重试上限；已确认的消息重启后不重复发送。
- 解除订阅立即停止新报告并撤销该订阅关联的交互权限；同一会话可同时专属绑定与公共订阅，加入订阅不夺走专属绑定。
- 定时任务通知沿用来源校验：任务通知只能投给其来源会话绑定的专属入口，不能借任务通知把其他会话内容送进专属 Bot；公共报告由订阅事件自动驱动，无需逐任务配置。

## 定向交互与审批闭环

- 回复一条公共报告，或用 `/to S7K2 再补一个测试`，文字只进入指定会话；未回复也未指定目标的普通文本不广播、不猜测最近报告。
- 显式目标与被回复消息冲突时明确拒绝；回复映射过期、会话删除、订阅解除时提示重新选择，不静默丢弃或误投。
- 该会话的提问卡片与审批按钮也会送到公共入口：按钮只携带短凭据，服务端重新鉴权并原子消费，双击、重放、跨 Bot 操作、旧按钮均不能产生第二次审批；桌面先处理后 IM 按钮失效。
- 公共入口本期仅支持定向文本：图片、语音、附件会被明确拒绝，不会忽略媒体后悄悄执行残余文字。专属 Bot 媒体能力不变。
- 同一轮对话的完整回复只回到发起入口；专属发起的轮次若该会话已订阅，公共入口收到一次完成报告，不重复整段流式内容。

## 桌面设置

- Telegram 设置拆分为「专属 Bot」与「公共 Bot」：分别展示 Token、配对状态、实际 Bot 身份、运行状态和错误；公共区提供操作者、订阅列表、投递问题（失败／不确定）与重置操作者入口。

## 安装与更新

- macOS Apple Silicon：下载 `ccmax-0.10.0-mac-arm64.dmg`，打开后拖入「应用程序」。
- 首次打开若被 Gatekeeper 拦截：在「系统设置 → 隐私与安全性」中点「仍要打开」，或在终端执行 `xattr -dr com.apple.quarantine /Applications/ccmax.app`。
- 已安装 v0.6.x–v0.9.x 的用户可直接用新 DMG 覆盖安装，配置与会话数据保持不变；公共 Bot 默认关闭，升级后无需任何操作。
