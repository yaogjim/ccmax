# ccmax v0.11.3

定时任务通知支持选择 Telegram 投递入口：创建任务时可选择通过**专属 Bot**、**公共 Bot** 或**两端同时**发送任务完成通知。旧任务文件不写新字段即保持原专属 Bot 行为，投递键不变。同步更新中英文文档。

> **安装范围与签名**：本版本仅提供 macOS Apple Silicon（ARM64）安装包，沿用该分支的本地自签名方式，未经 Apple Developer ID 签名和公证。首次打开可能被 Gatekeeper 拦截，请仅在确认来源可信后按下方步骤安装。Windows、Linux 和 Intel Mac 安装包不在本次发布范围内。

## 任务通知的 Telegram 投递入口

- 新建/编辑定时任务时，选择 `telegram` 通知渠道后可进一步选择投递入口：专属 Bot、公共 Bot 或两端 Bot；不选择则保持原有专属 Bot 行为。
- 选择公共 Bot 时要求公共 Bot 已开启且已绑定操作者（owner），否则创建界面直接提示先到「设置 → IM 适配器」完成开启或配对；选择两端时，收件人必须同时是公共 owner 与专属配对用户。
- 两端同时投递时各自独立：一端失败（含异常中断）不影响另一端，也不回退到另一入口；投递记录分别标注 `Telegram · 专属` 与 `Telegram · 公共`。
- 公共入口的授权来自服务端可信任务上下文（已登记且已结算的真实 run + 当前公共 owner + 允许的项目根目录），调用方传入的 run/task 字段一律不作为授权依据；上下文缺失时公共投递可见失败，不静默降级。
- `telegramEntrypoints` 持久化字段缺省（未设置或 `null`）等价于 `['dedicated']`；空数组、非数组、未知或重复取值均按坏字段可见失败，绝不静默退化为专属入口。公共入口使用独立幂等键，旧记录与旧键不受影响。

## 投递记录与任务列表

- 任务运行面板的投递明细按入口区分显示（`Telegram · 公共` / `Telegram · 专属`），每条记录标注实际走的 Bot 入口；旧记录缺省显示为专属。
- 新任务表单五语言文案（简中 / 繁中 / 英 / 日 / 韩）同步补齐，公共 Bot 未开启、未绑定 owner、两端收件人约束均有明确提示。

## 验证

- `env -u CALLER_DIR bun run check:server`：全部通过（含新增 cron-scheduler / scheduled-tasks / notificationService / persistence-upgrade 回归）。
- 持久化升级检查：`telegramEntrypoints` 旧文件（无该字段）加载行为与 v0.11.0 完全一致，已有旧 fixture 回归通过。
- 本地构建 `desktop/scripts/build-macos-arm64.sh`（dmg + zip，自签名，含 package-smoke 与签名链校验）通过。

## 安装与更新

- macOS Apple Silicon：下载 `ccmax-0.11.3-mac-arm64.dmg`，打开后拖入「应用程序」。
- 首次打开若被 Gatekeeper 拦截：在「系统设置 → 隐私与安全性」中点「仍要打开」，或在终端执行 `xattr -dr com.apple.quarantine /Applications/ccmax.app`。
- 已安装 v0.6.x–v0.11.x 的用户可直接用新 DMG 覆盖安装，配置、订阅、会话与定时任务数据保持不变。
