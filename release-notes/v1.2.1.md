# ccmax v1.2.1

macOS 免签名（ad-hoc）构建恢复自动更新能力。Squirrel.Mac 会拒绝 ad-hoc 签名的更新包，导致未签名发布无法在应用内升级；本版本在检测到当前应用为 ad-hoc 签名时自动改用替换式更新后端：下载 Release 的 zip 产物并校验 sha512，应用退出后替换 .app 包，失败时回滚旧版本。Developer ID 签名构建继续走原生更新通道，行为不变。

> **安装范围与签名**：本版本提供 macOS（ARM64 与 x64）和 Linux（x64 与 ARM64）安装包，其中 macOS 包未经 Apple Developer ID 签名和公证，首次打开可能被 Gatekeeper 拦截，请仅在确认来源可信后按 `install-macos-unsigned.sh` 的说明安装。Windows 安装包不在本次发布范围内。

## macOS 免签名构建的替换式更新

- 检测当前 .app 的 codesign 状态：Developer ID 签名构建继续使用原生 Squirrel 更新；ad-hoc 或未签名构建切换到替换式后端，两条通道互不影响。
- 下载按 CPU 架构选择正确的 zip 产物（ARM64 主机优先 arm64 包），流式计算 sha512 并与 Release 元数据比对，校验失败即删除已下载文件并报错，不会安装损坏的更新包。
- 安装阶段由独立脚本在应用退出后执行：等待进程退出 → 解压新包 → 替换 .app → 清除 quarantine 属性 → 启动新版本；替换或启动失败时自动恢复旧版本并重新打开，执行日志写入 `logs/update.log`。
- 下载进度沿用既有更新事件（Started / Progress / Finished），界面进度显示与原生更新一致；手动代理设置对替换式下载同样生效。

## 验证

- 更新器单元测试（updater / macUpdate / macReplaceUpdate，共 33 例）全部通过，含安装脚本真实替换与回滚执行的用例。
- Electron 主进程 TypeScript 类型检查（`tsc -p electron/tsconfig.json`）通过。
- 本版本未在本机执行打包编译；各平台安装包由 tag 触发的远端 CI 构建。

## 安装与更新

- 已安装 v1.2.0 的 macOS 用户：本版本起可在「设置 → 关于」中直接检查并安装更新，应用会自动完成下载与替换；也可照旧下载 dmg 手动覆盖安装。
- Linux 用户沿用 AppImage / deb 手动安装；配置、订阅、会话与定时任务数据在升级后保持不变。
