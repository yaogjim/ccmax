# ccmax v0.7.0

本次新增 **Agent 专属供应商与模型绑定**：主会话可以把独立任务交给使用另一家模型服务的 Agent，并在对话中查看它实际使用的供应商与模型。同时更新中英文 README 和功能截图，修复权限模式切换的循环导入问题。

> **安装范围与签名**：本版本仅提供 macOS Apple Silicon（ARM64）安装包，沿用该分支的本地自签名方式，未经 Apple Developer ID 签名和公证。首次打开可能被 Gatekeeper 拦截，请仅在确认来源可信后按下方步骤安装。Windows、Linux 和 Intel Mac 安装包不在本次发布范围内。

## Agent 专属模型

- 在「设置 → Agents → Agent 详情 → 运行环境」中，为单个 Agent 固定供应商与模型；支持选择已有模型或手动填写模型 ID，清除绑定后恢复跟随会话。
- 主会话的模型保持不变，固定 Agent 在独立后台进程中执行任务。列表与对话卡片展示供应商、模型及配置是否有效。
- 支持前台执行、后台执行和运行中转入后台；停止后台任务时同步停止对应执行进程。同一会话最多同时运行 3 个固定 Agent，超出上限立即报错。
- 固定 Agent 的费用和用量记在所选供应商上，不计入主会话的用量统计；权限请求仍需由主会话处理。
- 绑定只接受用户级或企业托管设置，项目设置不能改变任务的模型服务去向。企业托管绑定优先，在界面中只读。
- 供应商被删除或模型无法解析时明确报错，不自动回退到主会话模型。调用时另行指定的 `model` 不覆盖固定绑定。

### 使用边界

- **数据去向**：任务提示词以及该 Agent 读取的文件内容会发送到绑定的供应商，请先确认你信任该服务。
- 固定运行环境依赖桌面应用的本地服务；纯 CLI 会话调用固定 Agent 会报错。
- 与主会话共用工作目录，不支持独立 Worktree、其它工作目录或 fork；并发修改同一文件仍需由主控协调。
- 不支持由固定 Agent 或团队成员嵌套调用固定 Agent，也不支持在任务完成后通过 `SendMessage` 续聊或恢复。需要继续时重新分配完整任务。
- 团队计划成员仍使用计划中确认的运行环境，单个 Agent 的绑定不会覆盖团队计划。
- 请通过界面设置完整绑定；手工写入缺少供应商或模型字段的配置不会成为有效绑定。

详见 [子 Agent 与任务拆分](https://yaogjim.github.io/ccmax/desktop/agents)。

## 修复与回归验证

- 修复权限模式更新中的循环导入：使用 ESM 实时绑定，避免捕获尚未初始化的模块导出，防止主机应用批准计划或切换权限时出现 `transitionPermissionMode is not a function`。
- 补充连续进入、退出计划模式的回归测试，保留禁止未授权跳过权限检查的约束。

## 安装与更新

本版本仅提供 **macOS Apple Silicon（ARM64）** 安装包，桌面应用要求 macOS 12.0 及以上。Computer Use 原生助手的系统要求为 macOS 14.4 及以上；安装包结构与统一签名链验证不等同于实际桌面操作验证。

发布资产：

- `ccmax-0.7.0-mac-arm64.dmg`：首次安装。
- `ccmax-0.7.0-mac-arm64.zip`：自动更新使用的压缩包。
- 两份 `.blockmap`：更新差分数据。
- `latest-mac.yml`：版本与文件校验信息。
- `install-macos-unsigned.sh`：安装并移除隔离标记的辅助脚本。

安装包使用本地证书 `cu-helper-dev`，应用、后台服务与 Computer Use 助手共用同一证书签名链；它不属于 Apple Developer ID，且未经公证。

1. 从本 Release 的 Assets 下载 DMG 与 `install-macos-unsigned.sh`，放在同一目录。
2. 确认文件来源可信后，执行 `bash install-macos-unsigned.sh`。脚本会安装应用、移除隔离标记并启动。
3. 如需手动安装，将应用从 DMG 拖入「应用程序」，再执行 `xattr -dr com.apple.quarantine /Applications/ccmax.app`。
4. 已安装旧版本的用户可以在设置中检查更新；如果更新安装被系统拦截，可改用上述手动安装方式。
