# ccmax v1.2.0

本次版本集中加固 Agent Teams 的可靠性和身份边界，并补齐部署与运维能力：删除重建同名团队后，旧运行者不再能读到、领走或确认新实例的消息；Stop、交付验收和请求压缩的边界行为更确定；新增 Docker 部署工具链。

> **安装范围与签名**：本版本仅提供 macOS Apple Silicon（ARM64）安装包，沿用该分支的本地自签名方式，未经 Apple Developer ID 签名和公证。首次打开可能被 Gatekeeper 拦截，请仅在确认来源可信后按下方步骤安装。Windows、Linux 和 Intel Mac 安装包不在本次发布范围内。

## 消费侧实例隔离

- 每个消费者（lead、in-process 成员、pane 成员、process worker）在创建或可信恢复时绑定固定身份：团队创建元组、生命周期代次、成员实例 ID 和所属会话。读取、领取、确认和权限回执都在同一把锁内复核该身份。
- 删除并重建同名团队、或替换同名成员后，旧运行者的读取、领取、确认全部被拒绝，且不会写入新实例的 live 邮箱或已读历史；新实例仍能完整收到自己的消息。
- 缺实例身份的历史运行者不会被按当前名字自动补身份。自动接收停止并给出明确原因，历史仍可查看；恢复到原实例或显式重新加入时走可信绑定入口，并在界面文案上区分两种结果。
- 旧消息仍按原有信封规则兼容读取，不重写存量数据，不改变普通发信协议。

## 团队交付与 Stop

- 成员交付按版本记录，独立验收、退回原因和行动责任分离；同一版本不会反复要求确认。
- Stop 之后不再停留在「思考中」：只有同一团队身份的停止水位严格推进后才结束等待，倒序或缺失水位不会伪造回复或完成。
- 待命角色可以没有任务直接启动，首次启动按新会话处理；批准时冻结成员、任务与主控配置。

## 投递与请求边界

- 团队消息投递区分「已排队」「已送达」「被拒绝」：仅在 socket 真正发送后才确认，替换成员、Stop 取消或会话结束的未发送项不会投递，也不把排队成功当作已送达。
- 压缩请求与配置边界共享同一份预算，拒绝在临界窗口无界输出；失败时不跨请求复用旧的成功结果。
- 成员插话不再因用户回声被当成自己而丢弃；重复正文、批量、超时和旧数据都有覆盖。

## 桌面团队界面

- 团队画布、成员检查器和计划卡展示任务交付版本、退回原因和成员当前状态。
- 团队工作台按实例身份读取数据，旧团队的状态不会覆盖新团队。

## Docker 部署

- 新增 Docker 部署工具链与配套脚本，便于在容器内运行和升级。

## 验证与已知边界

- 服务端逐文件检查、桌面检查、持久兼容、策略、Provider 契约、聊天契约与 Agent Flow 门禁均通过；标准覆盖率门禁通过，变更行 91.78%（2959/3224），门槛 90%。
- 消费隔离的删除重建、消息身份碰撞和锁顺序均有确定性回归。
- 单进程插桩运行仍有少量已知失败，不影响上述逐文件门禁结论，相关修复继续推进。
- 真实 pane 启动/重连与浏览器整链验收尚未运行；使用本地自签名安装包时请自行评估风险。
