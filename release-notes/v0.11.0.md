# ccmax v0.11.0

公共 Bot 的订阅管理从纯文字命令升级为**交互式列表**：`/sessions` 和 `/subscriptions` 现在直接打开可点击的分页列表，按钮选择、批量订阅、逐项取消订阅都不再需要复制完整 `sessionId`。文字命令仍然可用。同时更新中英文 Telegram 文档。

> **安装范围与签名**：本版本仅提供 macOS Apple Silicon（ARM64）安装包，沿用该分支的本地自签名方式，未经 Apple Developer ID 签名和公证。首次打开可能被 Gatekeeper 拦截，请仅在确认来源可信后按下方步骤安装。Windows、Linux 和 Intel Mac 安装包不在本次发布范围内。

## 会话选择列表（/sessions）

- 发送 `/sessions` 打开可点击的会话列表：每行按钮显示「未选择 / 已选择 / 已订阅 · 会话标题 · 项目目录」，无需复制完整 `sessionId`；`/sessions 关键词` 按关键词搜索。
- 点击未订阅的会话加入本轮选择，再次点击只是取消本轮选择；点「订阅所选（N）」才真正订阅——确认前不会开始报告。点击已订阅条目不会取消订阅，真实订阅只能通过 `/subscriptions` 列表或 `/unsubscribe` 解除。
- 每页 20 条，上一页 / 下一页之间选择保留；「清空选择」只清本轮选择，不动真实订阅。新发 `/sessions`（包括换关键词）开启新一轮，旧列表按钮全部失效。
- 批量确认逐项显示「成功 / 已订阅 / 失败 · 标题 · 短编号或原因」；成功项移出待选，失败项保留可重试，成功项不回滚。只接收订阅后的事件，不补发历史报告。

## 订阅管理列表（/subscriptions）

- 分页查看真实订阅、稳定短编号与最近投递状态；点单项「取消订阅」先进入确认，点「返回」不修改订阅，只有「确认取消」才停止该会话的后续报告。
- 取消确认带订阅版本校验：等待确认期间订阅状态若被文字命令或其他途径改变，确认自动失效并提示重新选择，不会误删新状态。
- 解除订阅立即停发后续报告；未发送报告、关联回复与按钮按既有规则失效，不影响其他订阅。

## 列表失效规则

- 列表在服务重启、Bot 运行身份刷新（换 token、重置操作者、重新配对）、新同类命令开启新一轮或 14 天后失效；失效列表上的旧按钮点击后明确提示重开，不会执行任何操作。
- 按钮携带一次性短凭据，服务端对每个回调重新鉴权；重复点击同一按钮只回放该操作的结果提示，不产生第二次订阅变更。

## 体验与稳定性

- 列表更新就地编辑同一条 Telegram 消息（文字与按钮一起刷新），不再每次操作刷一条新消息；公共报告仍作为新消息发出。
- 回调按钮进入串行队列前先应答 Telegram，客户端按钮转圈立即停止；编辑内容与现状一致时 Telegram 返回的「message is not modified」按成功处理，不再误报失败。

## 安装与更新

- macOS Apple Silicon：下载 `ccmax-0.11.0-mac-arm64.dmg`，打开后拖入「应用程序」。
- 首次打开若被 Gatekeeper 拦截：在「系统设置 → 隐私与安全性」中点「仍要打开」，或在终端执行 `xattr -dr com.apple.quarantine /Applications/ccmax.app`。
- 已安装 v0.6.x–v0.10.x 的用户可直接用新 DMG 覆盖安装，配置、订阅与会话数据保持不变。
