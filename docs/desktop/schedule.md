# 定时任务

把一段提示词存下来，让它按时间自动跑。典型用法是每天早上审查昨天的提交、每周整理一次待办、每小时检查一遍某个服务的日志。

任务可以在桌面页面上手动建，也可以直接在对话里让 Claude 建，两者写的是同一批本地任务。

## 从哪进去

- **桌面页面** — 点侧边栏的「定时任务」打开任务列表页，右上角「＋ 新建任务」，在表单里逐个字段填写。
- **对话** — 直接在任意会话里说清要做什么、什么时候做，比如「每个工作日早上 9:30 帮我总结昨天的提交」。应用内置的 `LocalScheduledTask` 工具会把它落成一个本地任务，随后同样出现在任务列表页里。

任务列表页顶部有一条常驻提示，说的就是下面这件事。

:::warning
定时任务只在桌面应用打开、且电脑处于唤醒状态时运行。合上盖子、退出应用、关机，任务都不会跑，也不会补跑。它不是云端调度器——没有守在云端的进程替你计时，只有本机的本地服务活着、机器醒着的时候才会触发。
:::

## 用对话创建和管理

对话方式和表单等价，只是不用自己点字段。工具叫 `LocalScheduledTask`，它通过应用自己的本地接口读写任务，所以只在桌面应用运行时可用；应用没开时它不会出现。

- 创建时给一个 **cron 表达式**（5 段，本机本地时间：「分 时 日 月 星期」）和一段 **提示词**。「每个工作日 9:30」就是 `30 9 * * 1-5`。
- 「某个时刻提醒我一次」这类一次性任务，会让表达式只匹配那一个时刻，并标记为不重复执行。
- 任务由本地服务持久保存，重启应用后依然在；也可以随时回到任务列表页里管理。

对话里同样能列出、查看、修改、启用、禁用、删除已有任务，或让某条任务立刻跑一次。任务 id 由本地服务生成，改之前先让它列出来，不要自己编一个。

:::info
`/schedule` 说的是另一套东西：它创建在 Anthropic 云端运行的远程触发器，需要 claude.ai 账号和云端环境，在这个本地版本里没有启用。本地定时任务不要用它，用上面的侧栏页面或直接对话。
:::

## 新建任务的每个字段

![「新建定时任务」弹窗：名称、描述、提示词、频率与通知](../images/app/zh-CN/schedule-create.webp)

- **名称**（必填）— 列表里显示的标识，建议用短横线风格，比如 `daily-code-review`。
- **描述**（必填）— 一句话说明这个任务干什么，方便以后自己认出来。
- **提示词** — 真正发给 Claude 的内容。把上下文写足：要看哪些东西、关注什么、输出成什么格式。它跑的时候你不在旁边，没人给它补充说明。
- **权限** — 固定为「所有权限」，表单里不让选。提示词编辑器下面会直接标出这次运行的目录范围。因此：**工作目录一定要选到最小范围，提示词也要先自己读一遍**。
- **模型** — 单独指定，不跟随会话的默认模型。日常巡检类任务用便宜的模型就够。
- **工作目录** — 任务运行的项目目录。也可以开「独立工作树」，让任务在隔离的 Git worktree 里跑，不碰你的主分支。
- **频率** — 每 N 分钟 / 每 N 小时 / 每天 / 工作日（周一至周五）/ 指定星期几 / 每月 / 自定义 Cron 表达式。选「每天」这类时右边会多出一个时间选择器。自定义 Cron 的格式是「分 时 日 月 星期」，填错了下面会当场提示无效。
- **单次执行超时（秒）** — 可选。留空继承默认值：优先环境变量 `CC_HAHA_TASK_TIMEOUT_MS`，未设置时为 600 秒（10 分钟）。它只限制这条任务的单次运行，与普通聊天和 API 请求超时无关。
- **完成后推送通知** — 打开后可选通知渠道：桌面系统通知，以及已经配好的 IM 渠道（Telegram、飞书）。每选一个 IM 渠道，还要明确指定一个**通知收件人**。Telegram 可选专属 Bot、公共 Bot 或两端；专属与飞书从已配对账号中选择，公共只可选择公共 Bot 的 owner。没配过 IM 会提示你去 设置 → IM 接入 配置，步骤见[手机 H5 与 IM 接力](./remote.md)。

系统通知需要在 设置 → 通用 里先打开「启用系统通知」并授予系统权限。

任务会带一点随机延迟触发，避免整点一堆任务同时开跑。

## 通知发给谁

IM 通知必须指定明确的收件人，系统**不会**把任务结果广播给所有已配对用户。专属 Telegram 与飞书的收件人来自各自已配对账号；公共 Telegram 的收件人必须是公共 Bot 已配对的唯一操作者（owner）。访问白名单不构成通知授权。

Telegram 的「投递入口」支持专属、公共或两端。未选择入口的旧任务继续走专属 Bot。公共任务通知无需订阅任何会话，也不要求公共 owner 在专属配对表里；两端共用一个显式收件人，此人必须同时满足两个入口的身份要求。选公共后仍需明确选择收件人，编辑时不会自动替换失效的旧 owner。公共 Bot 的开启和配对步骤见 [Telegram](../im/telegram.md#打开公共-bot)。

每次公共发送及重试前，本地服务重新核对任务登记、已结束的真实运行、通知配置、收件人、公共 Bot 身份及允许项目目录。已删除或未登记的任务、伪造运行、非 owner 或被篡改的收件人会明确失败；身份变更不会改投新 Bot。任务通知只读，不建立回复会话或审批关联。两端投递独立记账，一端失败不抑制另一端；日志区分专属与公共，并显示已送达、失败或结果不确定。

如果收件人没配对、对不上唯一账号或根本不存在，这次投递会明确记为失败，不发给任何人，而不是悄悄群发。在对话里创建任务时也一样：用户没说清发给谁，就不要自己猜一个目标。

桌面通知走系统通知中心，不需要收件人，只要在 设置 → 通用 里打开「系统通知」并授予系统权限。

## 跑起来之后

任务卡片上有这些操作：

- **立即执行** — 不等下次触发，现在就跑一遍。新建任务后建议先手动跑一次，确认提示词写对了。
- **日志** — 打开执行记录，每次运行一行，带状态（运行中 / 已完成 / 失败 / 超时）和耗时。点「摘要」看输出片段，点「查看完整对话」跳到那次运行对应的完整会话。
- **编辑** — 改任何字段，包括频率。
- **禁用 / 启用** — 暂时停掉但不删。
- **删除** — 连同它的所有日志一起永久删除。

列表页顶部三个数字是总任务数、活跃、已禁用。

## 几个实践建议

1. **先手动跑一次再定频率。** 提示词的毛病在第一次运行就会暴露。
2. **工作目录选窄一点。** 任务以完整权限运行，目录范围就是它的活动边界。
3. **频率别太密。** 每分钟跑一次的任务很快会烧掉不少 token，也会把日志刷满。
4. **让它输出结论而不是过程。** 在提示词里明确要求「最后用三行总结」，通知里才看得下去。
