# 上游可靠性路线图

## 当前完整链路状态（2026-10-27 审计后）

已有主线为用户批准团队→角色按需启动→成员指令/历史回声→版本化交付及独立验收→Stop→恢复后按新指令续跑。前述能力已接线并保留离线及局部 UI 证据。压缩侧的 cap 合法性与 Azure 耗尽传播已于 2026-10-27 修复并有确定性及 loopback 证据（真实供应商未验证）；Teams 侧的 Stop 跨恢复、实例发送和等待结算仍是未闭合边界。权限政策已于 2026-10-27 选择 A：既有团队保留批准时权限上限，扩大需明确增量批准，更严格限制仍生效；实现合同与验收尚未闭合。**整链最低状态为 verified-partial，不是 accepted。**

## 完整路线总览

- D0/S0：文档隔离、本地基线和独立实现来源策略已有记录；不代表所有候选上游许可均已核实。

- S3：角色、消息、交付主链已实施；BG-T1/T2/T3、BG-D1、BG-V1 需要补缺与分层验收。
- 当前补缺路线：P1 已完成确定性修复验证；用户于 2026-10-27 授权继续后续阶段，并批准 P0-B 隔离行为探针与合同闭合。P2 Teams 纵向补缺→P3 近真实整链的开发授权有效，但设计仍 not-ready；不得把源码盘点或探针暴露缺陷算作生产修复。
